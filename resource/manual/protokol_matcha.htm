8.5. Протокол матча


Функция «Протокол матча» появилась в версии 1.6 и работает в тестовом режиме. Набор полей и шаблоны ещё могут меняться. Проверяйте документ перед официальной сдачей.
Кнопка «Протокол матча» в левом меню формирует файл Microsoft Word (.docx). Сначала открывается диалог «Данные протокола» — туда вводятся турнир, судьи, время и логотип. Затем программа подставляет данные матча (составы, голы, удаления, таймауты, броски) в выбранный шаблон и предлагает сохранить файл.

Шаблоны: resource/templates/protokol.docx (горизонтальный) и resource/templates/protokol_vertical.docx (вертикальный). Постоянные поля судей и турнира хранятся в секции [PROTOCOL] файла config.ini.
Как включить
Кнопка активна при одновременном выполнении условий:
  • SYSTEM.protocol = 1 в resource/config.ini;
  • режим двух команд: VID.vgame = 2 (для 4 и 6 команд кнопка отключена).

[SYSTEM]
protocol = 1
При попытке сохранить протокол в режиме 4/6 команд появится сообщение: «Протокол ведётся только для игры двух команд.»

В тестовой версии 1.6 отдельного переключателя во вкладке «Настройки» может не быть — параметр protocol задаётся в config.ini. Секция [PROTOCOL] создаётся программой автоматически.
Как сохранить протокол
1. Проведите матч в режиме 2 команд: загрузите составы (4.9), ведите счёт, удаления и таймауты.
2. Для авторов голов используйте полный ввод (goal_simplified = 0) — иначе в протоколе не будет номеров G / A1 / A2 (6.9).
3. В левом меню нажмите «Протокол матча».
4. В диалоге «Данные протокола» выберите формат, заполните поля матча и судей, при необходимости укажите логотип.
5. Нажмите «Сформировать».
6. Укажите путь сохранения (имя по умолчанию: protocol_КомандаА_КомандаБ.docx).
7. При успехе — сообщение «Протокол сохранён»; событие пишется в лог приложения.

Значения по умолчанию при первом открытии:
  • Вид соревнований — из PROTOCOL.tournament, иначе из колонтитула TEXT.header;
  • Логотип — из PROTOCOL.logo, иначе логотип лиги IMG.leagues;
  • Формат — PROTOCOL.layout (horizontal или vertical).

Судей и место проведения удобно заполнить один раз — они запомнятся до следующего матча. Номер игры, зрителей, фактическое время и тренеров вводите каждый раз заново.

Составы (до 22 игроков на команду)
resource/rosters/home.json и guest.json: номер, ФИО, роль (К/А), амплуа (ВР/З/Н). Сначала вратари по номерам, затем полевые
Голы (до 22 строк)
Журналы HOME / GUEST: время от начала матча, автор и ассистенты из «ГОЛ - ПЛЮС …». Учитывается «ГОЛ - МИНУС»
Удаления (до 22 строк)
Журнал: строки вида «УДАЛЕНИЯ ИГРОКА … №… на N мин. ПО ПРИЧИНЕ …». Командный штраф → номер К. Снятие из списка удаляет последнюю запись. Минуты приводятся к целым минутам (в т.ч. после упрощённого ввода)

Счёт по периодам 1–3 и итого
По периоду в строках голов журнала
Таймаут команды
Время первого таймаута из журнала (MM:SS от начала матча)
Броски
Текущие счётчики бросков хозяев и гостей
Вратари в сводке
Номер первого вратаря (амплуа ВР) из состава
Время игры вратарей
Автозаполнение из журнала: строка 00:00 (стартовые вратари из состава) и каждая СМЕНА ВРАТАРЯ / СНЯТИЕ ВРАТАРЯ С ВОРОТ с временем от начала матча. Нужны полный ввод гола, состав и действия кнопки «Вратарь» (6.6)
Что вводится в диалоге (раньше было пусто)
Эти поля больше не остаются пустыми «навсегда» — их заполняют в диалоге перед выгрузкой:
  • вид соревнований, место проведения, номер игры, зрители;
  • плановое время начала и фактические начало / окончание матча;
  • судьи, секретарь, хронометрист (судья времени);
  • тренеры команд А и Б;
  • логотип бланка.
Поле город отдельно в диалоге нет — при необходимости укажите город в «Место проведения» или допишите в Word.
Секция [PROTOCOL] в config.ini

[PROTOCOL]
tournament = ...
place = ...
referee1 = ...
referee2 = ...
timekeeper = ...
secretary = ...
logo = resource/img/leagues/...
layout = horizontal
После нажатия «Сформировать» постоянные поля перезаписываются в конфиг. Разовые поля матча (время, номер игры, зрители, тренеры) в файл не сохраняются.
Файл .game хранит и постоянные, и разовые поля. После импорта игры в диалог подставляются только постоянные из [PROTOCOL]; разовые нужно заполнить вручную снова (12.2).
Ограничения тестового режима
  • Только режим 2 команд (vgame = 2).
  • Нужны шаблоны protokol.docx и/или protokol_vertical.docx.
  • Максимум 22 игрока и 22 события (гола / удаления) на команду.
  • Без составов в rosters/ блок игроков пустой.
  • Без полного ввода гола — нет номеров авторов.
  • Штрафной бросок (ШБ) из упрощённого диалога пишется в журнал отдельно и не попадает в таблицу удалений протокола.
  • Овертайм / буллиты в разбивке по периодам 1–3 не выделены отдельно.
  • Формат ориентирован на хоккейный бланк.
 

Для теста: protocol = 1, vgame = 2, выключить упрощённый гол → загрузить составы → провести матч → «Протокол матча» → заполнить диалог → выбрать формат → сохранить .docx → проверить в Word.
